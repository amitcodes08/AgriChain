  frontend/lib/api.ts parsed the wrong error shape. The backend returns error: {
  message, details: [{ field, message }] }, but the client read
  payload.errors[].path — so every validation failure surfaced as a generic
  "Request failed (400)" instead of highlighting the offending field. Now it
  reads details[].field, and the keys line up with the Zod paths the form uses.

  artefact from each boot rather than a stale copy.
